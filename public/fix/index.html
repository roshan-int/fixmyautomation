How to troubleshoot an existing automation

  1. Find the first failure. Don't start by reviewing the entire workflow. Identify the first activity that behaves differently.
  2. Find the last successful run. A previous successful execution gives you something concrete to compare against.
  3. Ask what changed. Look at the application, browser, Excel, packages, Windows environment, robot and deployment.
  4. Make the smallest safe change. Avoid changing multiple unrelated parts of a production workflow at the same time.
  5. Test the original scenario. A workflow opening successfully is not enough. Test the operation that originally failed.
Why we focus on repair: An automation that has been running successfully for months or years usually contains valuable business logic that doesn't need to be thrown away because one part stopped working.
